## 1. 한 장 요약

**"0.5B 경량 모델 3개의 저마진 앙상블 + OOF 검증 룰 스택"** — 대회 취지(경량·고속 의사결정)에 정면으로 부합.

```
입력 (test.jsonl, 30,000행)
  │  current_v1 직렬화 (session_meta + history + current_prompt → 텍스트, len 384)
  ▼

  │
  │ 저마진 라우팅: top1-top2 logit margin < 1.0 인 행만 (34.1% — 준현 실측)

[model_c] amw4 recipe seed42 · INT4 (292MB)  ┘ → z-centered logit 평균 (3-member)
  │
  ▼

  budget-zone 룰(R1/R1b/R1c…) + R1i + seq-exec + Weak4 action-margin 게이트
  │
  ▼

```

- **베이스 모델**: naver-hyperclovax/HyperCLOVAX-SEED-Text-Instruct-0.5B (0.47B — 대회 최경량급)
- **양자화**: 자체 구현 int8 row-wise codec(무게 50%) + int4 group-128 codec(멤버용) → 3모델을 1GB 안에
- **최종 챔피언 main**: amw4 recipe seed7070 — 기존 챔피언 손실(sieve×condα KD, M8 교사)에 **Weak4-스코프 action-margin 보조항** 추가. λ는 그리드서치가 아니라 gradient-노름 비율 0.10 1회 자동보정(s7070 실측 λ=0.1312). ※ trioT 자기증류(0.7972)는 mainT 계보 — 최종 amw4는 **원본 M8 teacher** 사용, 두 계보 혼동 금지 (준현 명세 §1)

## 3. 추론 속도 (본선 배점 10%)

| 구성 | 서버 실측 | 비고 |
|---|---|---|
| 최종 트리오팩 | **7:15~7:23** / 10:00 | 동적 패딩, eager attention |
| 단일모델팩 | 5:52~6:10 | 참고치 |
| 시간초과 실패 사례 | 0.8B ep3 (m8_ep3) 2건 | 스크린 단계에서 이미 예상 |

- **속도 엔지니어링 핵심 발견**: 추론시간은 len 캡이 아니라 **실제 토큰 수**를 따름(동적 패딩) → len 캡 축소는 무효, 직렬화 자체를 짧게 하거나 모델을 줄여야 함 → 0.5B 선택의 근거
- torch.compile 검토 → T4에서 eager 대비 이득 없음(warm 포함 43% 느림) 실측 후 기각
- 시간예산 산식: forward 비중 0.95, 단독 ≤0.6B급 / 앙상블 합계 ≤0.6B급 → 트리오는 저마진 라우팅(34.1%만 2·3모델 통과)으로 시간 안에 우겨넣음
- **라우팅 3점 dose-response (전부 Public 실측, 준현 §5)**: @1.25 = 39.7% 라우팅 = 0.7960 (과다) / **@1.0 = 34.1% = 0.7977 (최적)** / @0.75 = ~28.5% = 0.79739 (과소) — 1.0이 양쪽에서 브래키팅된 실측 최적점

## ✅ 준현 확인 4건 — 전부 해소 (07-16, `junhyun/finals_amw4_handoff.md`)

1. **amw4 정의** ✅ — L_total = L_base + λ·L_AM. L_AM = Weak4 true-label 행에서 teacher-기준 hard-negative top-3에 대한 SmoothL1 마진 매칭(T=3). λ = gradient-노름 비율 0.10 1회 결정론 보정 (s7070: 0.1312). 구현: `train_transformer.py` 커밋 `070338a`
2. **amhyb vs amw4_7070m10** ✅ — 차이는 **model_c 한 자리** (구 recipe s7070 → amw4 s42). Public 10자리 완전 동률 = 히든셋 예측 플립 0행 → "멤버 정체성 예측-불활성" 통제실험. 동률 중 최속 amhyb(7:15)가 챔피언 등재
3. **model_b/c 명세** ✅ — b = 구 recipe s909 INT4(두 팩 공통), c(amhyb) = amw4 s42 INT4 (코덱 패리티 170/170 검증). main = amw4 s7070 INT8 (fidelity 511/512)
4. **margin 1.0 복원 이유** ✅ — AM 항이 마진 분포를 압축 → @1.25는 라우팅 39.7%로 팽창, 추가 밴드 오류율 19.4%뿐(구 main 41.5% 손익분기)이라 "이미 맞는 행"에 멤버 간섭. 3점 dose-response로 1.0이 실측 최적점 확인
