# `weak4` 문제 정리

> [보관 메모 — 진산] 준현이 07-16 06:08 팀채널에 업로드 (F0BH66LCD9D).
> 07-11에 성낙준 교수님 설명용으로 작성한 것 — 발표 슬라이드 "문제 정의" 파트와 QnA(비전문가 심사위원 대응)에 그대로 쓸 수 있는 톤.

`weak4` 문제는 쉽게 말하면, **서로 아주 비슷한 네 행동 중 "에이전트가 실제로 선택한 하나"를 맞혀야 하는 문제**라서 어렵습니다.

Weak4는 다음 네 클래스입니다.

- `list_directory`: 폴더 구조 보기
- `read_file`: 특정 파일 읽기
- `grep_search`: 파일 내용에서 문자열 찾기
- `glob_pattern`: 조건에 맞는 파일 목록 찾기

예를 들어 "설정이 어디에 정의되어 있는지 확인해줘"라는 요청에는 네 행동이 모두 그럴듯합니다. 폴더를 먼저 볼 수도 있고, 설정 파일들을 glob으로 찾거나, 키워드를 grep하거나, 이미 파일을 안다면 바로 읽을 수도 있습니다. 즉, **사람이 봐도 정답 후보가 여러 개**입니다.

더 어려운 이유는 다음과 같습니다.

1. 문장만으로 구분하기 어렵습니다.
   `find`, `where`, 파일명, 경로 같은 단어가 네 클래스에 모두 나타납니다. "find"가 있다고 반드시 `grep_search`인 것도 아닙니다.

2. 직전 작업의 미세한 차이가 중요합니다.
   방금 폴더 목록을 봤는지, grep 결과가 나왔는지, 특정 파일이 언급됐는지에 따라 다음 행동이 달라집니다. 긴 history에서 이 작은 단서를 정확히 찾아야 합니다.

3. 데이터의 정답은 '가장 합리적인 행동'이 아닐 수 있습니다.
   이 대회는 이상적인 에이전트의 판단이 아니라, 생성 과정에서 **실제로 선택된 행동**을 예측합니다. 같은 상황에서도 생성 에이전트가 폴더를 한 번 더 보거나, 바로 읽거나, 검색부터 하는 식의 정책 습관과 우연성이 섞여 있습니다.

4. 하나를 고치면 다른 클래스가 망가집니다.
   네 클래스는 서로 닫힌 혼동 집단입니다. 예를 들어 `grep_search` 점수를 일괄적으로 올리면 grep은 좋아져도 원래 `read_file`, `list_directory`, `glob_pattern`이던 사례들이 grep으로 넘어가 전체 점수는 떨어질 수 있습니다.

5. 전문가 모델도 같은 한계에 걸립니다.
   Weak4만 따로 학습한 specialist를 붙여 보았지만, 최적 혼합값이 사실상 "specialist를 사용하지 않음"인 `alpha=0`이었습니다. 더 강한 teacher도 개선은 하지만 동일한 주요 혼동을 공유했습니다.

리레이블 실험도 이 문제를 잘 보여줍니다. GPT-5.6의 의미 판단에서 기록된 Weak4 행동을 "허용 가능한 선택"으로 본 비율은 약 30%였고, 특히 `list_directory`는 5.2%, `glob_pattern`은 15.0%였습니다. 이것이 인간 기준의 절대적 오라벨률이라는 뜻은 아니지만, **의미적으로 좋아 보이는 행동과 대회가 요구하는 행동 사이에 큰 간격이 있다**는 강한 증거입니다.

그래서 현재 잘 통한 방법도 "깔끔한 경계를 새로 배우기"가 아니었습니다. 오히려:

- 의심스러운 정답의 학습 압력을 줄이는 consensus sieve
- Weak4에서는 hard label보다 teacher 분포를 조금 더 따르는 conditional-alpha KD

처럼 **애매한 정답을 강제로 외우지 않게 하는 방법**이 효과적이었습니다.

한 문장으로 요약하면:

> Weak4는 "무엇이 합리적인 다음 행동인가?"가 아니라, "여러 합리적인 행동 중 데이터 생성 에이전트가 이번에는 무엇을 골랐는가?"를 맞혀야 해서 어렵습니다.
