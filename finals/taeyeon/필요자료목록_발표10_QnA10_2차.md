## 2. gen_fig 서사 정합성 확인 (스크립트 실측)

`make_pres_figures.py` 코드 확인 결과, gen_fig들은 **md 최종 서사(amhyb)로 이미 갱신돼 있음**:
- **gen_fig1**: 6페이즈 = P1인코더 → P2디코더 → P3 HCX+KD → P4 sieve → P5 앙상블+룰 → **P6 자기증류·Weak4-AM 0.7977**. 최종점·상승폭 정확.
- **gen_fig3**: `main HCX-0.5B trio-KD INT8 568MB` + `margin<1.0 (~24%만)` + `0.5B×3` + `7분15초 / 1005.6MB`. **md amhyb 서사와 일치** (1005.6MB·margin 1.0·트리오).

→ 즉 제가 불일치리포트에서 지적한 pptx 옛 서사(512MB/0.7972/10룰)는 **gen_fig에서 이미 최신으로 교체됨.** pptx 본문 슬라이드만 이 그림들에 맞춰 갱신하면 됨.

## 3. 🔴 남은 이슈 — gen_fig3에 sparse SVC·leak_lookup 없음

gen_fig3 아키텍처는 `main + model_b + model_c` (LLM 3앙상블)로만 그려짐. **B-1에서 발견한 실물의 두 요소가 빠짐:**
- **sparse SVC (TF-IDF 하이브리드)** — script에 `sparse_svc.pkl` 결합 로직 존재
- **leak_lookup override** — script 최종 단계 `pred_map.update(leak_overrides)`

**이건 "틀렸다"기보다 "발표 서사 결정 대기":**
- 발표에서 **sparse/leak를 밝히기로** 하면 → gen_fig3에 2블록 추가 (스크립트 편집)
- **안 밝히면** (LLM 앙상블 중심 서사로) → 현 상태 유지, 단 **코드검증 QnA에서 "sparse_svc.pkl/leak_lookup.json.gz 뭐냐" 반드시 나옴** → QnA 백업(§5)으로 대비

→ **팀 결정 필요** (B-1 §4 leak_lookup 판단과 묶임). script_mgn125.py는 준현 확인 대기이므로, 확정 후 반영.
