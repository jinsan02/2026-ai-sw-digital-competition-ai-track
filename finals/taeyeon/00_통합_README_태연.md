## 4. 🔴 미결 리스크 — leak_lookup (반드시 팀 결정)

**B-1 대조에서 발견.** 상세는 `B1_script대조결과.md §4`. 요약:

- script.py 최종 단계가 `pred_map.update(leak_overrides)`로 모델+룰 예측을 **덮어씀.**
- leak_lookup은 4 tier:
  - `positional`/`aligned` — **test 세트 내부** 히스토리로 답 복구 (외부 정보 無, 정당한 추론 여지 큼)
  - `train_prompt`/`train_prompt_last` — **train 데이터**로 만든 prompt→label 룩업 (train→test 매핑). 주석 원문: "holdout precision 0.978 vs **model ~0.74**"
- 변수명 `leak_`, 주석 "Recover labels" → 작성자도 leakage 계열로 인식.

**팀이 확인·결정할 것:**
1. 최종 팩(amhyb_m10)에 `leak_lookup.json.gz` **동봉 여부** (동봉됐으면 0.79766 점수에 train override가 이미 기여)
2. 제출 로그의 "Leak overrides: total=N ... train_prompt_last=X" 출력으로 실제 발동 확인
3. 대회 규칙상 train 라벨 prompt 매핑 허용 범위 판단 (규칙 원문 대조)
4. → 준현 명세에 **"leak_lookup tier별 최종 활성 내역"** 항목 추가 권장

**태연 입장**: 코드가 뭘 하는지만 정확히 보고. 정당성 판단은 팀 몫. 다만 **발표·코드제출 나가기 전 반드시 명시적으로 다뤄야 함.**
