### B-1. script.py 추론 파이프라인 설명 (발표 슬라이드 5 소스, 1페이지)

**추론 파이프라인 — 실행 순서**

```
test.jsonl (30,000행)
  │
① 직렬화  current_v1: {session_meta + history + current_prompt} → 단일 텍스트, max_len 384
  │        (동적 패딩 — 실제 토큰 수만큼만, len 캡은 상한일 뿐)
  ▼
② 모델 로드  main(INT8, 568MB) 상주 · model_b/c(INT4, 292MB×2)는 저마진 통과분 처리 시 사용
  │           HF_HUB_OFFLINE=1, eager attention (compile 미사용 — T4서 무효 실측)
  ▼
③ main 전 행 forward → top1/top2 logit margin 계산
  │
④ 저마진 라우팅  margin < 1.0 인 행(~24%)만 model_b·model_c 추가 forward
  │              나머지 ~76%는 main 단독 확정 (여기서 시간 예산 확보)
  ▼
⑤ z-centered logit 평균  통과 행에 한해 3-member 로짓을 z-정규화 후 평균 → argmax
  │
⑥ 룰 스택 12종 적용  budget-zone(R1/R1b/R1c…) + R1i + seq-exec + Weak4 action-margin 게이트
  │                   (전부 OOF 5-fold×교차시드 통과분, 룰 간 충돌 0행)
  ▼
output/submission.csv
```

**시간 분해 (서버 T4 실측, 총 7:23 / 제한 10:00)**

| 단계 | 비중 | 근거 |
|---|---|---|
| forward (main 전행 + 멤버 24%) | **~95%** | 채점로그 회귀: 추론시간 = f(실제 토큰 수), v5 6:55/m7 8:55 = 토큰비 0.80과 일치 |
| 직렬화 + 토크나이즈 | ~4% | tokenize-batch 1024 |
| 룰 스택 후처리 | <1% | 벡터 연산, 무시 가능 |

- **핵심 발견 1**: 시간 병목은 len 캡이 아니라 **실제 토큰 수**(동적 패딩) → 직렬화를 짧게 하거나 모델을 줄이는 것만 유효, 이게 0.5B 선택의 근거.
- **핵심 발견 2**: 저마진 라우팅으로 2·3모델 통과를 24%로 제한 → **3모델 앙상블인데 7:23**에 우겨넣음(단일팩 5:52 대비 +1:30만 지불).
- forward별 세부 시간(main / b / c 각각 초 단위)은 서버 재측정 필요 — 현재 초안엔 총합만 있음. **진산님/준현님, script.py에 단계별 `time.perf_counter()` 찍은 로그가 어디 있는지** 있으면 공유 요청. 없으면 "forward 95%, 멤버 통과 24%" 수준으로만 발표.

⚠️ **미상 포인트**: 초안 어디에도 script.py 실물이 없어서 위 설명은 `01`·`02`·`04` 서술 기반 재구성입니다. 최종 제출 zip(`rfinal_amw4_7070m10.zip`)의 실제 script.py와 대조해서 라우팅 임계값(1.0 확정 맞는지, 초안엔 margin 1.25→1.0 재축소 이력이 있음)·룰 순서를 확정해야 합니다. **누가 최종 zip 갖고 있는지** 알려주면 제가 script.py 뜯어서 이 페이지 정합성 맞추겠습니다.

## C) 슬라이드 13(팀 역할표기) 합의 의견

진산님이 스레드에 요청한 "focal 발견·R1 발굴 크레딧" 건. 제 입장:

- **크레딧은 실제 기여자 기준으로 정확히**가 맞다고 봅니다. 부풀리거나 몰아주면 QnA에서 "이건 누가 했냐" 물었을 때 답이 꼬임.
- `06` QnA 15번의 역할 분담(진산=검증/하니스/인프라 · 원주=데이터분석/감사 · 준현=모델고도화/KD레인 · 태연=추론코드/제출관리)이 실제와 맞으면 이걸 슬라이드 13 베이스로.
- **제 파트 관련**: 저는 추론 파이프라인·제출 관리 + **인코더 레인 탐색(mdeberta, 기각) 및 직렬화 강건성 probe**로 표기 희망. `03`의 강건성 probe(TTA 근거 기각·표현섭동 강건 164행)가 제 트랙이라 이건 남겨주면 좋겠습니다. 다만 인코더 레인은 어차피 기각축이라 슬라이드 13엔 "추론/제출/강건성 검증" 정도로 압축돼도 무방.
- **focal·R1 크레딧**: focal loss(γ2.0)는 공통 레시피라 특정인 크레딧보다 "팀 표준"으로, R1(budget-zone) 발굴은 원주님 EDA(budget-zone 발견)가 기원이라 `07`·`03`대로 **원주님 크레딧**이 맞아 보입니다. R1 계열 룰 스택 검증(5-fold 게이트)은 진산님 하니스. → 발굴/검증 분리해서 둘 다 표기 제안.

**요약 제안**: 슬라이드 13은 QnA 15번 4인 분담을 베이스로, ①focal=팀표준 ②R1 발굴=원주/검증=진산 분리 ③제 항목에 강건성 probe 포함. 이견 있으면 스레드에서 조율하시죠.
