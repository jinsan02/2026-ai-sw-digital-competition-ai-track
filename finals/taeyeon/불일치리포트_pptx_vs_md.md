# 불일치 리포트 — 실물 pptx ↔ md 초안 (2026-07-15, 태연)

> **[07-15 회신 반영] 대부분 해소.** 진산님 확정: ① 최종 선택본 = **amhyb_m10(7:15)** → 발표는 amhyb(제출본) 기준 통일 ② script.py = **mgn125 확정**(SHA f286f21d), 파이프라인 뼈대 최종과 동일 ③ 1위 **0.79878**/격차 **0.00112**. **남은 미결: (a) model 폴더 용량 512 vs 1005MB (b) leak_lookup 규칙 판단(→B1 §4).**

> **결론 먼저**: 실물 `본선발표_에이전트행동예측.pptx`(14장)와 종합본 md들이 **서로 다른 제출본을 기준으로 작성됨.** pptx가 한 세대 뒤쳐진 버전(0.7972/10룰/trio만). 최종 제출본 amhyb_m10 기준으로 pptx 갱신 필요.

## 2. 왜 갈렸나 (추정)

- pptx는 **07-15 낮 시점**(2026zip.zip에 있던 원본, 마감 전) 서사로 보임 → 0.7972, 512MB, 442초.
- md 종합본은 **마감 후 최종 제출본(amhyb_m10)** 기준으로 갱신 → 0.7977, 1005MB, 7:15.
- 즉 **pptx가 md보다 한 세대 뒤쳐진 버전.** 자기증류(+0.0006→0.7972→0.7977 amw4/amhyb)와 최종 팩 교체가 pptx에 미반영.

⚠️ **단, 이건 추정.** 실제로 512MB 단일계열이 최종일 수도 있음(추론 442초가 amhyb 7:15보다 빠름?? — 오히려 pptx 442초 < md 435초 언급도 있어 혼란). **어느 zip이 Dacon 최종 선택본이고 그 script.py·모델 구성이 뭔지**가 유일한 진실 소스. → B-1 script.py 대조로 확정 가능.

## 3. 결정 옵션

**옵션 A — md(최종 제출본) 기준으로 pptx 전면 갱신**
- 발표가 실제 제출본(amhyb 0.7977/1005MB)과 일치 → 코드검증·QnA에서 안전.
- 작업량: pptx 슬라이드 1·3·5·6·8·9·12 숫자·차트 갱신. 자기증류 서사 슬라이드 6에 추가.
- **권장** (심사위원이 제출 zip과 발표를 대조하면 pptx 옛값이 걸림).

**옵션 B — pptx(512MB/0.7972) 기준 유지**
- pptx 손 덜 대지만, **제출본과 발표가 불일치** → "발표는 0.7972인데 제출은 0.7977?" 질문 위험.
- 512MB가 실제 제출이면 이게 맞지만, md가 1005MB라 근거 약함.

**옵션 C — script.py 대조로 진실 먼저 확정 후 결정**
- `rfinal_mgn125.zip`(or 최종 amhyb zip) script.py + model 폴더 크기 확인 → 512MB냐 1005MB냐, trio냐 단일이냐 **팩트 확정** → 그 기준으로 pptx/md 양쪽 통일.
- **가장 안전.** 태연이 script.py만 받으면 30분 내 판정 가능.

## 4. 태연 권고

**옵션 C → A**: script.py(+가능하면 model 폴더 용량)로 진실 확정하고, 십중팔구 md(제출본) 기준이 맞을 테니 pptx를 그쪽으로 갱신. 지금 스켈레톤은 pptx 14장 구조를 뼈대로 잡아뒀으니, 숫자만 확정되면 바로 채움.
